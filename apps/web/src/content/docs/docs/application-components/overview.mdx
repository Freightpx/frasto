Application components encode repeated product structures: shells, resource views, filters, details, settings, and activity. This layer is Frasto's main distinction from a generic primitive library.

:::caution[Planned specifications]
These pages define expected behavior and design boundaries. They do not represent stable package exports.
:::

## Inventory

| Component | Primary responsibility |
| --- | --- |
| AppShell | application frame and regions |
| Sidebar | sectioned application navigation |
| PageHeader | page context, heading, metadata, actions |
| Stat | compact quantitative summary |
| SearchInput | clearable search intent |
| Table | semantic, presentational table structure |
| ResourceTable | real business data and row operations |
| FilterBar | search, filters, active criteria, clear action |
| Pagination | page navigation and result context |
| EmptyState | explain absent data and next action |
| DetailLayout | resource information, relations, activity, actions |
| SettingsLayout | settings navigation and content |
| ActivityFeed | chronological domain events |

## Design rule

Application components compose with ordinary HTML and core primitives. They do not fetch their own records or require a product to adopt a Frasto backend architecture.

`Table` owns native table structure, density, alignment, and overflow presentation. `ResourceTable` owns the typed row-and-column abstraction and composes `Table`; neither component fetches, sorts, paginates, or mutates application data.

## Definition before build

Each component must define meaningful composition slots, data states, narrow-layout transformation, keyboard behavior, accessible structure, and ownership boundaries before implementation begins.
