title: Documentation contributions
description: Keep design decisions, component behavior, examples, and implementation synchronized.
---

Documentation is part of Frasto's public product and review surface.

## Component page standard

A mature page contains:

1. overview and status
2. preview
3. installation or import
4. basic usage
5. anatomy
6. variants and sizes
7. states
8. props, slots, and events
9. accessibility
10. responsive behavior
11. examples
12. best practices and anti-patterns

## Examples

Examples must compile against released APIs, remain minimal, and use realistic content. Planned specifications should not invent code that appears available.

## Voice

Write directly, concisely, and technically. Explain the decision and its practical consequence. Avoid marketing language in API guidance.

## Synchronization

API changes update docs in the same contribution. Stable behavior described only in source comments is undocumented behavior.

## Review

Check headings, links, code validity, light/dark presentation, narrow layouts, and whether accessibility or responsive requirements are explicit.
