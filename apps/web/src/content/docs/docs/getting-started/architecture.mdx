## Foundations

Semantic tokens, typography, spacing, layout, interaction states, accessibility, responsive behavior, and content rules form the shared language.

## Components

Reusable interface building blocks span actions, forms, display, feedback, navigation, overlays, data, and layout. Components remain backend-agnostic and useful outside any one application type.

## Patterns

Patterns specify how components cooperate across complete tasks: search and filtering, resource lists, dashboards, settings, CRUD, bulk actions, and loading, empty, and error states.

## Guides and recipes

Guides teach focused implementation decisions. Recipes pressure-test the system in realistic interfaces. Dashboard, CRM, settings, and Acme Cloud material remain valid examples without defining the library's identity.

## Future ecosystem layers

Mature UI foundations may later support Frasto Icons, Blocks, Pages, and SaaS. These are separate layers built from evidence gathered through real use.

## Package boundary

The current library uses one package, `@freightpx/frasto`. Package splitting requires evidence from adoption and maintenance, not speculation.
