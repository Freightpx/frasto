## 1. Define the decision

Write down what someone should understand or do after scanning the page. This decides which metrics, exceptions, activity, and records belong above the fold.

## 2. Establish hierarchy

Use `PageHeader`, a restrained stat group, one primary analysis region, and the most operational list. Avoid making every metric an equal card.

## 3. Format at the application boundary

Prepare labels, values, comparison periods, units, and trend meaning before rendering. The UI should not infer whether a numeric change is good or bad.

## 4. Design independent states

Allow activity or a chart to fail without erasing useful stats and records. Define loading, first use, stale data, partial failure, and no-access states.

## 5. Transform for narrow screens

Preserve importance through source order. Reduce grid columns, stack analysis regions, and choose an explicit table strategy.

## 6. Validate meaning

Check keyboard order, chart summaries, contrast, long values, zoom, dark mode, and reduced motion.
