## Built for application work

Frasto UI is intentionally more application-oriented than a generic primitive library. The goal is to make recurring SaaS structures—resource lists, settings, detail screens, navigation, filters, data states, and actions—feel coherent from the beginning.

<CardGrid>
  <Card title="Astro first">
    Render useful HTML on the server. Add client behavior only when the interaction needs it.
  </Card>
  <Card title="SaaS patterns">
    Treat AppShell, ResourceTable, FilterBar, DetailLayout, and SettingsLayout as first-class product primitives.
  </Card>
  <Card title="Backend agnostic">
    Bring data from Astro Actions, REST, GraphQL, Supabase, Appwrite, your own API, or anything else.
  </Card>
  <Card title="Designed for daily use">
    Clear hierarchy, restrained color, quiet borders, compact density, and accessible states.
  </Card>
</CardGrid>

## Freightpx direction

The default visual language is editorial and neutral: warm surfaces, near-black primary actions, thin dividers, restrained radius, minimal shadow, and typography doing most of the hierarchy work.

> **Clarity first. Craft throughout.**

## Current status

The project is in its documentation-first foundation phase. We are defining the design language, component contracts, architecture, and contribution rules before implementing the first public component set.
