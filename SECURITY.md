# Security Policy

## Supported versions

| Version | Security status |
| --- | --- |
| `0.1.0-alpha.x` | active alpha line; security fixes are targeted but production support is not guaranteed |
| older development snapshots | unsupported |

Alpha security fixes are applied to the active release line and documented in the changelog. Components remain Experimental until they individually meet the Beta evidence gate.

## Reporting a vulnerability

Do not publish exploit details in a public issue. Use GitHub's private vulnerability reporting flow from the repository **Security** tab and include:

- affected component or package
- reproduction conditions
- potential impact
- a minimal proof of concept when safe
- any suggested mitigation

Maintainers will acknowledge a complete report, assess severity, coordinate a fix, and credit the reporter when requested and appropriate.

Repository owners should keep GitHub private vulnerability reporting enabled before the first public package release.
