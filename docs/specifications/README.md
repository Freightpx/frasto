# Specifications

Specifications describe work that is not necessarily implemented or publicly available. They exist for design and engineering review and must not be copied into consumer documentation as released APIs.

Use this area for:

- planned component contracts
- future application-layer research
- reusable interface pattern specifications
- recipe and pressure-testing plans

## Current specification areas

- [Component inventory](./component-inventory/)
- [Planned components](./planned-components/)
- [Future application layer](./future-application-layer/)
- [Patterns](./patterns/)
- [Recipes](./recipes/)
- [Deferred guides](./guides/)

When a specification is implemented, move its user-facing behavior into the public component documentation and retain only implementation rationale that remains useful to contributors.
