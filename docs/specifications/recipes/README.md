title: Recipes
description: Realistic interfaces used to validate Frasto components and patterns together.
---

Recipes are production-shaped examples, not isolated component galleries. They use concrete content, believable density, responsive layouts, dark mode, and complete states across varied interface types.

## What recipes validate

- component APIs compose without awkward adapters
- page hierarchy remains clear across routes
- application density feels practical
- loading, empty, error, and partial states are coherent
- keyboard and touch interaction work across components
- light and dark themes feel like one product
- missing components become visible before release

## Data policy

Initial recipes use mock TypeScript data. A database is unnecessary for validating presentation contracts and application patterns.

## Recipe families

Marketing, content, commerce, SaaS, CRM, CMS, ERP/inventory, admin, and customer portal examples may follow. They should reuse the same system rather than introduce separate visual languages.

## First recipe

[Acme Cloud](./acme-cloud.md) is a preserved planned SaaS recipe and a possible future Frasto Pages candidate. It does not block component-library expansion or public alpha.
